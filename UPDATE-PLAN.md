# M Generation II POS update system

The application is prepared for production updates using `electron-updater`.

## Separation of concerns

- Application files are installed/updated by Electron Builder.
- The SQLite database lives in Electron's userData directory and is not packaged into the installer.
- Database schema changes are handled by migrations before the POS is used.
- Updates are checked automatically after startup in packaged builds and can be checked manually from Settings.

## Before enabling production updates

Set a real HTTPS update feed instead of the placeholder in `package.json`:

```text
https://YOUR-UPDATE-SERVER.example.com/m-generation-ii-pos/
```

For a generic provider, the release directory must contain the metadata and installer artifacts generated by Electron Builder (for example `latest.yml` plus the Windows installer for Windows releases, and the corresponding macOS metadata/artifacts for macOS releases).

Do not expose a writable release directory publicly. Releases should be uploaded through a controlled deployment process.

## Recommended release process

1. Make and test code changes.
2. Add a database migration if the schema changes.
3. Increment the application version in `package.json`.
4. Run the full POS regression tests.
5. Build Windows and/or macOS installers.
6. Upload the generated update artifacts to the configured HTTPS feed.
7. Install the release on a test machine and verify database migration and rollback/backup behavior.
8. Only then make the release available to production machines.
